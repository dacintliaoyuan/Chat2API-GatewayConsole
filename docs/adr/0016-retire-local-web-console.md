# 本机 web 控制台退役，桌面版成为唯一本机界面

## 状态

已接受（2026-11-22）

## 背景

一套前端按构建期角色产出两个控制台：本机角色 `web/src/local` 构建 `web/dist`，由 8001 托管；云端角色 `web/src/cloud` 构建 `web/dist-cloud`，由 8002 托管。桌面版 `desktop/` 是独立的 Slint 实例，默认 `127.0.0.1:7999`、测试 `127.0.0.1:7998`。2026-11-22 用户决定：桌面版成为唯一本机界面，本机 web 控制台（页面源码 + 本机构建）全部退役，**但前提是桌面版确认可发布**（功能对等 + 实机验收通过）。

## 决策

- 本机 web 控制台退役：`web/src/local` 页面源码与 `web/dist` 本机构建一起退役；桌面版成为唯一本机界面。
- 退役前提：桌面版先达到功能对等——`web/src/local` 的全部功能迁移到桌面版，且桌面版确认可发布（实机验收通过）。退役前 `web/src/local` 仍是功能对等基线。
- 云端 `web/src/cloud` 与 8002 不受影响；云端分享链继续用浏览器页面。
- 8001 的去向在页面退役后评估：页面退役后它不再是用户入口；是否保留为 API 宿主或一起退役另定，不在本次决策内。
- 本机回退面在退役后消失：退役前必须完成迁移与实机验收，之后本机功能回归只覆盖桌面版。

## 考虑过的选项

- 只退役页面、保留本机构建：用户选择全部退役（页面 + 本机构建），因为桌面版可发布后两者都不再需要。
- 先退役再补功能：不选；退役前没有功能对等就没有回退面，风险不可接受。
- 保留 8001 作为长期 API 宿主：暂不决定；页面退役后 8001 不再是用户入口，等退役实施时再定。

## 后果

- 退役不是本次迁移 spec 的实施内容，而是 App 确认可发布后的后续动作；spec 只交付「全部本机功能迁移 + 实机验收」。
- `一键部署本机网关.bat` 的「打开控制台」步骤要随页面退役调整；构建与 8000/8001 启停保持到 8001 去向确定。
- 本机浏览器控制台的前端回归（`web/` 的 `check:um` 等）在退役后只覆盖共享规则与云端页面，不再覆盖本机页面。
- 退役后 `web/dist` 不再由本机构建产出；`web/src/local` 的领域词汇与 ADR 保留作历史证据。

相关：ADR 0001、ADR 0012、ADR 0015。
