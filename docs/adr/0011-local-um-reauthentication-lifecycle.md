# 本机 UM 重新认证的触发、等待与完成

2026-11-18，本机出现后台认证未恢复、强制可见登录窗口很快关闭、UMPASS 已预填但未自动提交、Duo 自动通过后控制台仍提示人工确认四个现象。操作记录确认过 `network_error`、`umpass_autofill_protected` 和 Duo 等待期间提前结束的控制台操作。最初掉线的触发来源和闪退的具体关闭原因仍待复现。

本机 8000 网关统一持有认证恢复轮次。8001 控制台跟踪同一轮次的实际进度。可见登录暂时无法核验时保留同一个 Edge 窗口，直到核验成功、本人关闭窗口或本轮截止。Duo 自行通过时，控制台在凭据核验成功后显示「已登录」。

本决定适用于 Windows 本机 8000/8001。它取代 ADR 0008 中本机遇到 Duo 即要求人工接管、结束控制台等待或自动打开可见窗口的条款，并补充 ADR 0005 的可见窗口生命周期。

## 1. 掉线后的自动重登录

上游显式拒绝 UM 凭据，或后台核验确认缺少凭据时，由 8000 启动一次后台重新认证。同一实例的业务请求、后台巡检和控制台共享该轮次。网络中断或核验超时进入「暂时无法核验」，按现有后台核验机制再次检查。恢复需要人工时，显示具体原因和「继续登录」。本人点击后才打开 Edge。仍在进行的恢复由控制台直接观察。

- [ ] 使用模拟上游分别验证业务请求收到认证拒绝，以及没有业务请求时巡检确认失效。两个场景都能触发后台登录，重叠触发只启动一次。后台恢复成功后，后续请求可用。
- [ ] 模拟网络错误后恢复。核验未知时不启动登录。再次核验确认凭据有效时恢复为「已登录」，确认凭据被拒时进入后台登录。
- [ ] 模拟后台到达人工接管。确认状态包含具体原因，本机点击「继续登录」才启动可见 Edge。重复点击和刷新都不启动额外窗口。

### 已进入后台登录轮次后的核验

2026-11-20，本机后台 Playwright 轮次读到浏览器会话凭据后，8000 请求 `/api/models` 时断连，本轮以 `verification_unknown:ConnectionError` 结束，表单提交次数为零。同一台电脑的已登录 Edge 使用另一份会话凭据访问同一接口时取得有效响应，8000 仍使用原先保存的凭据。断连发生在哪一层仍待确认。

后台轮次取得待核验凭据后，连接中断或探测超时进入「正在核验登录结果」。保留同一轮及后台浏览器，在原截止时间内对同一凭据串行复查，沿用现有退避和业务请求等待预算。8000 核验通过后保存并发布凭据。若 UM 明确返回 401 或 403，丢弃被拒凭据，继续同一轮的登录流程。持续无法核验直到截止，或本轮被取消时，释放浏览器及 profile 锁，丢弃待核验凭据，并记录结果。持续无法核验时，8001 显示原因和实际下一次后台复查时间。

同一轮的专用 Edge 若已成功读取符合契约的模型目录，而 8000 核验仍未通过，8001 显示「网页登录正常，网关待核验」。只有 8000 自己核验通过并发布凭据后，才显示「已登录」。

- [ ] 模拟同一份新凭据第一次核验断连、第二次核验通过。确认后台浏览器和轮次各只启动一次，凭据通过前不落盘，通过后只保存并发布一次，`/ready` 返回 200。
- [ ] 模拟专用 Edge 返回有效目录、8000 核验仍失败。确认 8001 显示「网页登录正常，网关待核验」，直到 8000 自己核验通过才切换到「已登录」。
- [ ] 分别模拟待核验凭据收到 401 或 403、持续断连直至原截止时间，以及等待期间取消。确认明确拒绝后原轮次继续登录，持续断连或取消后资源释放，未通过核验的凭据不落盘。持续断连时核对 8001 显示的原因和下一次实际复查时间。
- [ ] 通过实际 Windows 本机 8000/8001 复验后台恢复，核验通过后经 8000 完成一次真实模型请求，并记录脱敏的轮次、核验结果和请求结果。

## 2. 强制可见登录的核验与窗口生命周期

可见 Edge 中取得待核验的 token 后，短暂网络问题或探测超时进入「正在核验登录结果」。在本轮剩余时间内串行复查同一凭据并保留当前窗口。待核验的凭据只用于本轮核验，核验成功后走现有正常关闭和保存流程。明确拒绝时显示原因，并在同一窗口回到可继续登录的页面。本人关闭窗口或本轮截止时结束核验，释放浏览器和 profile 锁。

- [ ] 模拟同一 token 两次暂不可核验，随后有效。全程只启动一个 Edge 窗口，UI 保持本轮核验中，成功后才显示「已登录」并保存。
- [ ] 分别模拟持续不可核验至手动关闭、持续不可核验至本轮截止、以及明确拒绝后重新登录。结果分别体现取消、超时及拒绝，未核验或被拒的 token 未进入持久存储。
- [ ] 在实际 Windows 可见登录入口验证临时网络故障期间窗口保持打开。复查受原轮次截止时间约束，临时错误、轮询或刷新均不会续期。

## 3. 「继续登录」后的 UMPASS 表单提交

点击「继续登录」后，网关在本轮的可信 UMPASS 页面确认账号和密码栏已就绪，且提交按钮可唯一识别时，自动提交一次并观察结果。若 Edge 的预填保护仍要求本人操作，窗口保持打开，控制台提示「Edge 已预填，请在 UMPASS 页面点击登录」。此时使用 Edge 页面本身完成交互。明确的账号密码拒绝进入人工处理，防止重复提交旧凭据。

- [ ] 真实 Edge 已预填且表单可确认时，点击控制台「继续登录」后，无需再手动点击 UMPASS 登录，提交次数为一次。
- [ ] 用真实 Edge 或可重复的浏览器夹具覆盖受保护的预填。窗口保持打开并显示明确的操作提示。本人点击官网按钮后，原轮次继续。
- [ ] 覆盖表单缺字段、提交按钮不唯一和明确拒绝。状态能分别指明下一步，自动提交仅在已确认可信页面与唯一表单时发生。

## 4. Duo 自动通过与人工确认

到达 Duo 阶段时先显示「正在完成 Duo 验证」。只有页面证据表明需要本人确认，才显示具体操作提示。控制台用同一轮次的后续状态更新界面。状态读取走只读路径，可在登录等待期间读取。会改变认证状态的操作仍受互斥约束。

- [ ] 模拟跳转经过 Duo 并自行返回。页面依次显示处理中、核验中和「已登录」，整个流程无需再次点击确认或启动新一轮。
- [ ] 模拟确需本人确认的 Duo。页面给出明确提示并保持本轮。批准后自动显示「已登录」，取消或截止后显示实际结果。
- [ ] 用 Windows 8001 在登录期间连续刷新总览。刷新能够读取同一轮的进度，避免与登录争用独占锁而产生 `lock_open_failed`。重复触发登录可识别当前轮次，互斥和取消仍可验证。

## 回归与实施边界

先用 8000 的模拟上游与浏览器夹具锁定状态转换、截止时间和窗口数量，再走 8001 实际动作入口与 Windows Edge 验收整个流程。现场证据记录触发来源、时间、轮次、状态和结果，凭据留在原存储。第 2 项优先复现窗口关闭条件，第 3 项用真实 Edge 验证可自动提交的条件。等待间隔沿用现有配置和本轮预算，避免引入独立的长等待时间。
