# 本机模型入口在网关重启时保持可用

2026-11-21，本机 8000 的模型处理进程意外退出，守护在约 2 分钟后重新拉起。期间多个项目的模型请求中断。决定把客户端一直使用的 `127.0.0.1:8000` 做成独立运行的本机模型 API 入口，由执行端负责恢复项目任务。这样所有本机客户端都能使用同一入口，执行端也能依据项目进度判断哪些操作可继续。

## 入口与模型处理进程

- 入口与模型处理进程分别运行。模型处理进程重启期间，入口保持监听 `127.0.0.1:8000`。内部连接由实现决定，客户端继续使用同一个模型 API 端口。8001 继续提供本机管理和诊断。
- 当服务仍处于应运行状态，且守护正在恢复意外退出的模型处理进程时，入口最多保留尚未转发的请求 3 分钟。模型处理进程就绪后再转发一次。请求取消后从等待队列移除。排队容量和请求体大小需要有界，超出时返回可识别的结果。
- 3 分钟到期时释放 HTTP 等待，返回执行端可识别的恢复等待超时。执行端保存任务进度并进入暂停，确认服务恢复后自动继续。从等待到暂停的转换只消耗一份等待预算。
- 已转发的请求可能已经执行，即使入口尚未收到任何输出。入口不得把这类请求当成排队请求重新发送。已开始的响应流中断时，由执行端根据已确认的进度接续任务。
- 继续遵守 [ADR 0013](0013-process-supervision-boundary.md) 的运行意图和守护职责。显式停止和退出 App 走原有停止流程。UM 会话恢复使用 [ADR 0011](0011-local-um-reauthentication-lifecycle.md) 的认证等待预算。云端 8002/8003 及桌面 App 的交付继续按现有决策。

## 本机 8000 的 UM 上游恢复等待

2026-11-24，UM 流式响应中断，后续请求遇到 503。8000 入口和模型处理进程持续运行，后台重新认证也成功。决定为确认的 UM 上游故障增加 **UM 上游恢复等待**。以下规则是已确认、待实现的行为，本次范围为本机 8000。

- 收到明确的上游不可用信号（如 `no healthy upstream`）时，后续模型请求进入等待。只有单条断流、超时或普通 5xx 时，先触发共享复查，复查确认仍不可用后才开始拦住新请求。故障记录仍按现有契约记录每次最终观察。
- 以实际向 UM 发送请求为界。尚未发送的请求可以等待，包括已进入模型处理进程的请求。所有等待者共享同一轮复查，各自使用原总截止时间的剩余预算。等待、复查和放行均不重置截止时间。保持有界排队，取消后及时释放等待名额，超时返回带明确上游恢复等待原因的 503。此前已发送的请求继续使用现有重试与流式错误规则。
- 用当前有效凭据取得新鲜、契约有效的模型目录后，先放行一条实际在等待的请求。它完整成功后，再逐步放行其余请求，受现有并发限制约束。探测失败、业务请求再次遇到上游不可用时，等待者按原截止时间继续等。请求级 4xx 或取消无法证明模型服务恢复，下一条仍按单条试放行处理。
- 本机存活探测、上游故障记录和认证状态各自有独立的证据。模型目录恢复可以结束原故障记录，放开业务队列还需要一条实际请求完整成功。401 或认证拒绝继续走 ADR 0011，认证等待仍消耗原预算。进程意外退出继续走本 ADR 的网关恢复等待。

### 本机 8000 上游恢复验收

- 用隔离实例分别返回 `no healthy upstream`、单条流截断后共享复查成功、普通 5xx 后共享复查仍失败。核对进入等待的条件及同一轮共享复查，确认 8000 继续监听。
- 同时发送多个模型请求，其中至少一个已经被模型处理进程接收但还没发给 UM。目录恢复时只发出一条，等它完整成功后再逐步放行。分别用再次断流、请求级 4xx 和取消验证单条试放行的失败和资源释放。等待中的请求到截止或取消后，UM 未收到该请求。
- 验证等待消耗各自原总预算，持续不可用时返回带明确原因的 503。已发出的流中断后，等待队列不会重新接收这条请求。模拟 401 时继续沿用登录流程及既有预算。

## 执行端任务接续

- 执行端保留任务标识、最后确认的进度和已完成工具的结果。网关恢复后，从这份进度自动继续。已完成的工具动作只复用先前结果。
- 工具动作已经发出但结果未知时，先查询目标系统。确认已执行就采用实际结果，确认未执行才可重试。查不清时只暂停该动作和依赖它的后续步骤，其他项目可继续。
- 执行端能力是自动接续的前置条件。先核查实际使用的执行端是否能识别等待超时、保存进度并在网关恢复时唤醒任务。HTTP 入口只能在自己运行期间保留等待。入口自身中断时，由执行端重新连接并按已确认的进度恢复任务。

## 验收

- 在本机隔离实例与多个项目请求中让模型处理进程意外退出。验证入口保持监听，尚未转发的请求在 3 分钟内恢复后各转发一次。验证取消、队列上限和显式停止。
- 验证超过 3 分钟时，入口释放该请求，执行端留下可见的暂停原因并保留进度。恢复后以同一个任务标识自动继续。
- 分别中断「还没收到输出但已经转发」的请求和已输出一部分的流。核对入口没有重发原请求，执行端从已确认的任务进度继续。
- 用一个可查询的工具写操作验证三种结果。已完成时复用结果，未执行时可重试，无法确认时只暂停受影响的任务分支。并行项目继续运行。
