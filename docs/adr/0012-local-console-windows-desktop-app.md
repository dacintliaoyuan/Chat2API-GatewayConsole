# 本地控制台桌面版优先适配 Windows 并以性能选型

这是本机功能完善后的长期计划，首期覆盖本机 UM 网关和控制台。首版优先适配和优化 Windows，默认随用户登录 Windows 启动并直接进入系统托盘，用户可在设置里关闭自启。关闭主窗口后应用留在系统托盘，托盘入口恢复已有窗口。保留现有本机管理流程，允许为性能重做桌面主窗口。

## 应用与服务的边界

现有架构由 8000 提供模型 API 和 UM 认证恢复，8001 提供浏览器控制台及管理接口。Slint 原型可复用 8001。正式桌面版由 Slint 承接状态总览、首次登录和账号管理、用量、请求诊断与实时日志。App 自身只开放一个回环 TCP 端口供模型客户端使用，默认 7999，可在设置中修改。Slint 通过本机进程间接口访问状态、日志、用量和登录管理。具体传输方式由实施设计确定。

桌面应用提供窗口、托盘和通知。Slint 界面和 Rust 网关各自运行在独立进程。手动打开 App 或随 Windows 登录启动时，App 接入已经运行的本实例网关，或在网关未运行时拉起它。关闭主窗口时 App 收起到托盘，网关继续服务模型请求。界面意外退出时，网关继续处理在途请求，重新打开 App 可接回原网关。从托盘选择「退出 App」时，立即停止本实例网关并中断在途请求，再退出桌面应用。监督机制将该动作视为主动停止。首版驻留范围为已登录的 Windows 用户会话。人工接管继续按 ADR 0011 执行，由本人通过控制台打开可见 Edge。 [ADR 0011](0011-local-um-reauthentication-lifecycle.md) · [ADR 0013](0013-process-supervision-boundary.md)

正式桌面版首次打开时初始化独立的本机环境。用量账本与运行日志从空白开始，账号状态从未配置开始，用户可进入首次登录流程。旧控制台的配置、账本、日志、凭据和浏览器会话均不导入。

首次打开时可跳过 UM 登录并进入总览。总览将 UM 登录显示为「尚未登录」，提供「配置账号」入口。用户此时可查看网关状态、设置模型 API 端口和检查日志，之后可从总览进入首次登录流程。

开发和验收可将测试实例设为 `127.0.0.1:7998`，与现用 8000/8001 同时运行。测试实例使用独立的配置、凭据、Edge profile、账本、日志和进程监督状态，界面及停止操作均按实例归属连接。

应用收起到托盘后，仅在需要用户操作时弹出 Windows 通知，例如继续登录、确认 Duo 或确认账号。自动恢复成功等进展更新托盘和窗口状态。

## 技术与界面方向

桌面前端采用 Slint，用 `.slint` 描述界面和交互，由 Rust 处理应用状态并读取网关状态和日志。用现有浏览器控制台作为 Windows 性能基线。 [Slint 桌面渲染](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backend_winit/)

主窗口沿用现有主题、字体和语义化样式。左侧是导航，中间显示当前页面，右侧详情按需展开。关闭请求详情后，列表保留筛选条件和滚动位置。窗口与托盘交互遵循 Windows 习惯。首版界面使用简体中文。首页分别显示服务运行、UM 认证和上游可用性，说明下一步可执行的操作。状态用文字和图标表达，详细错误码以及请求、账本和日志放在诊断页面。 [前端样式变量](../../web/src/shell/tokens.css) · [Windows 无障碍指南](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-overview)

总览采用状态优先布局，先显示网关运行、UM 登录和上游状态，再显示用量趋势。用量趋势提供柱状图与折线图切换。切换时沿用相同的时间范围、指标和数据。悬停查看时段数值，点击后在图表内固定该时段的数值，页面留在总览。需要逐条查看时，由用户从左侧导航打开「请求与诊断」。

## UM 账号与密码

参考 Magpie 的账号管理入口，在「模型与设置」放置一张「UM 账号」卡片，显示已保存的账号和本实例网关的认证状态。录入或更新账号密码时打开独立表单，密码输入默认遮挡。账号卡片提供「更新账号密码」和「清除已保存的账号密码」，需要人工操作时提供「继续登录」。首页也显示认证状态并提供同一个「继续登录」入口。 [Magpie 账号管理说明](https://usemagpie.ai/docs/start)

用户可在桌面 App 中录入并选择记住 UM 账号和密码。本实例网关统一管理重新认证。专用 Edge 在可信的 UMPASS 官方页上账号和密码栏都为空时，网关使用本机保存的这组账号密码补填。如果页面账号与保存的账号一致且密码栏为空，只补填密码。确认表单就绪且能唯一识别登录按钮后，每轮自动提交一次。Edge 要求本人操作或 Duo 需要确认时，App 显示原因并提供「继续登录」。 [ADR 0011](0011-local-um-reauthentication-lifecycle.md)

账号密码由 App 管理，保存在该用户的本机应用数据目录 `%LOCALAPPDATA%\Chat2API\credentials.json`，明文存储、权限 0600（2026-11-19 决定，不用 DPAPI，也不走 Windows Credential Manager 或 Edge 密码管理器）。网关通过环境变量 `CHAT2API_UM_ACCOUNT` / `CHAT2API_UM_PASSWORD` 接收这组账号密码，网关重启后无需单独解锁。凭据文件不可读或格式损坏时，App 提示凭据不可用并提供重新录入入口。日志只记录补填和核验结果。 [Magpie 账号管理说明](https://usemagpie.ai/docs/start)

如果 UMPASS 页面已填的账号和 App 保存的账号不同，网关暂停自动补填与提交，保留页面已有内容，由 App 提示用户确认使用哪个账号。

## 实时日志

桌面版从本机内部接口接收日志事件。日志页打开时加载最近记录，之后按事件 ID 增量接收和去重。断线、睡眠唤醒或重新打开窗口时，从上次位置补读。历史筛选继续使用分页接口。运行日志按事件发生时间展示请求已接收、重试和失败等进度，账本在请求结束后记录最终用量，两边通过请求 ID 关联。 [现有日志读取](../../web/src/local/um-data/read.ts)

界面批量追加新记录，长列表只渲染可见行。用户查看历史时保留滚动位置，显示「有新日志」供用户跳回。关闭到托盘后暂停列表刷新，继续显示必要的状态通知。 [Slint ListView](https://docs.slint.dev/latest/docs/slint/reference/std-widgets/views/listview/)

## 性能基线

在同一台 Windows 机器上，以 8000／8001 和现有浏览器控制台为基线，在同一版本、数据量和负载下测量桌面原型。记录前后端各自开销以及整套进程的总开销。先使用可重复的上游夹具测量网关开销，再用实际 UM 请求验证端到端体验。

- **后台与桌面。** 记录冷启动到首次可操作、托盘恢复到窗口可操作的耗时，以及主窗口打开、关闭到托盘后的 CPU 和内存。观察窗口关闭后的刷新活动。
- **网关与控制台。** 记录 8000 的首个流式输出耗时、并发吞吐和 p95 延迟，以及查询长账本和日志时的延迟、CPU 和内存。比较窗口打开、托盘驻留及桌面应用退出时的请求表现。
- **页面。** 记录首页可操作时间、账本和日志列表的打开与滚动表现。根据结果评估按需加载、列表渲染、轮询频率和动效的成本，再为实际工作负载定量化目标。
- **日志及时性。** 用同一台 Windows 机器和相同事件负载测量日志写入到前台列表可见的延迟。原型阶段的待验证目标为 p95 ≤ 500 毫秒。记录连续写入时的滚动表现、断线补读结果，以及启用日志订阅前后 8000 流式请求延迟的变化。

## 后续跨平台与手机反代

首版将 Windows 专用的托盘、自启、进程管理和浏览器交互留在平台入口。核心网关、请求协议、控制台页面及接口可独立复用。后续根据目标设备的系统生命周期、网络和资源预算评估平台适配。

手机反代作为后续可行性评估。分别考虑手机作为客户端访问本机网关，以及手机承载反代进程。前者复用网关接口并单独确定访问边界。后者先验证目标系统的后台持续运行、网络切换、耗电和认证接管，再决定实现形态。 [控制台访问边界](../../GLOSSARY.md)

## 升级与端口切换

需要重启本机服务的升级由用户点击「更新」开始。先等网关当前正在处理的请求自然结束，再重启服务并核验就绪。

在设置中更改模型 API 端口时，先检查目标端口，再等待当前正在处理的模型请求结束，然后切换监听地址并核验新地址。目标端口被占用或新地址启动失败时，显示原因并保留或恢复原地址。

## 原型验证

- 首轮 Slint 原型聚焦状态总览和实时日志，在相同数据量和负载下对照现有浏览器控制台记录 Windows 实测结果。
- 在 Windows 登录后启动桌面应用，关闭窗口后用托盘恢复。重复打开入口时复用原窗口。在窗口关闭期间向本实例的模型 API 发起请求，确认服务可继续使用。
- 分别验证手动打开与随 Windows 登录启动。网关未运行时自动拉起，已运行时接入原实例。在流式请求期间模拟界面意外退出，确认请求正常完成，重新打开 App 可连接同一网关。
- 在已有旧控制台配置、账本、日志与登录会话的 Windows 用户下首次打开正式桌面版，确认初始化独立环境，账本与日志从空白开始，并能进入首次登录流程。
- 在未配置账号的实例上跳过首次登录，确认进入总览并显示「尚未登录」。验证状态、端口设置和日志可访问，再通过「配置账号」进入首次登录流程。
- 在一个流式模型请求尚未结束时从托盘选择「退出 App」，确认请求立即中断、本机网关停止、桌面应用退出，且监督机制识别为主动停止。
- 验证默认自启直接进入托盘，在设置中关闭后下次登录 Windows 时保持关闭。模拟自动登录恢复及人工接管，确认只有需要本人操作时弹出 Windows 通知。
- 正式版验收时，确认 App 实例只监听配置的回环模型 API 端口，默认 `127.0.0.1:7999`。使用 `127.0.0.1:7998` 试跑时，核对测试实例的 TCP 监听、数据和启停操作与现用 8000/8001 隔离。通过 Slint 完成首次登录，查看用量、请求诊断和实时日志。需要人工接管时打开可见 Edge，同一轮核验通过后同步更新窗口和托盘状态。
- 验证账号卡片可录入、更新和清除已保存的账号密码，更新表单的密码栏初始为空。保存后账号卡片显示已保存的账号以及本实例网关的认证状态。
- 在桌面 App 保存测试账号密码后，确认落盘内容为明文 `credentials.json`，权限 0600。在同一 Windows 用户会话下重启 App 和本实例网关，直接触发后台重登。在可信的 UMPASS 官方页分别呈现空表单、同账号但缺密码两种情况，确认网关能读取、补齐缺失字段并提交一次，核验通过后窗口与托盘显示「已登录」。Duo 需要本人确认时，验证 App 显示对应提示并跟踪同一轮结果。
- 模拟凭据文件不可读或格式损坏，确认 App 提示凭据不可用，用户可重新录入，网关等待可用凭据后再继续补填。
- App 保存账号 A 时，在 UMPASS 页面预填账号 B 并留空密码。验证账号 B 与空密码栏保持原样，自动提交次数为零，App 提示确认账号。
- 验证右侧请求详情关闭后保留列表筛选和滚动位置。验证 Windows 浅色和深色主题、键盘焦点、缩放及睡眠唤醒后的主要操作。按性能基线记录结果。
- 在一个流式模型请求尚未结束时点击「更新」，确认该请求正常结束后才重启服务，并验证升级后发出的请求可以正常完成。
- 在流式请求尚未结束时更改模型 API 端口，确认该请求正常结束后才切换监听，并在新地址完成后续请求。模拟目标端口已被占用，确认 App 显示原因且原地址继续服务。
