# 本地控制台桌面版优先适配 Windows 并以性能选型

这是本机功能完善后的长期计划，首期实施范围为本机 8000 和 8001。首版优先适配和优化 Windows，在用户登录 Windows 后运行，可选择随登录启动。关闭主窗口后应用留在系统托盘，托盘入口恢复已有窗口。保留现有本机管理流程，允许为性能重做桌面主窗口。

## 应用与服务的边界

8000 负责网关和 UM 认证恢复，8001 提供本地控制台与管理接口。桌面应用提供窗口、托盘和通知，沿用现有服务启动与监督机制。关闭窗口保持 8000 和 8001 的服务状态。建议将「退出桌面应用」和「停止本机服务」作为独立操作，分别触发应用退出和显式服务停止。首版驻留范围为已登录的 Windows 用户会话。人工接管继续按 ADR 0011 执行，由本人通过控制台打开可见 Edge。 [本机控制台启动入口](../../scripts/Open-GatewayConsole.ps1) · [ADR 0011](0011-local-um-reauthentication-lifecycle.md)

## 技术与界面方向

桌面前端采用 Slint，用 `.slint` 描述界面和交互，由 Rust 处理应用状态并从 8001 读取状态和日志。用现有浏览器控制台作为 Windows 性能基线。 [Slint 桌面渲染](https://docs.slint.dev/latest/docs/slint/guide/backends-and-renderers/backend_winit/)

主窗口沿用现有主题、字体和语义化样式。左侧是导航，中间显示当前页面，右侧详情按需展开。关闭请求详情后，列表保留筛选条件和滚动位置。窗口与托盘交互遵循 Windows 习惯。首版界面使用简体中文。首页分别显示服务运行、UM 认证和上游可用性，说明下一步可执行的操作。状态用文字和图标表达，详细错误码以及请求、账本和日志放在诊断页面。 [前端样式变量](../../web/src/shell/tokens.css) · [Windows 无障碍指南](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-overview)

在总览点击用量图表中的时段时，在图表内显示该时段的数值，页面留在总览。需要逐条查看时，由用户从左侧导航打开「请求与诊断」。

## UM 账号与密码

用户可在桌面 App 中录入并选择记住 UM 账号和密码。8000 仍统一管理重新认证。专用 Edge 在可信的 UMPASS 官方页上账号和密码栏都为空时，8000 使用本机保存的这组账号密码补填。确认表单就绪且能唯一识别登录按钮后，每轮自动提交一次。Edge 要求本人操作或 Duo 需要确认时，App 显示原因并提供「继续登录」。 [ADR 0011](0011-local-um-reauthentication-lifecycle.md)

## 实时日志

桌面版使用 8001 提供的本机日志事件流。日志页打开时加载最近记录，之后按事件 ID 增量接收和去重。断线、睡眠唤醒或重新打开窗口时，从上次位置补读。历史筛选继续使用分页接口。运行日志按事件发生时间展示请求已接收、重试和失败等进度，账本在请求结束后记录最终用量，两边通过请求 ID 关联。 [现有日志读取](../../web/src/local/um-data/read.ts) · [SSE 断线续接](https://html.spec.whatwg.org/multipage/server-sent-events.html)

界面批量追加新记录，长列表只渲染可见行。用户查看历史时保留滚动位置，显示「有新日志」供用户跳回。关闭到托盘后暂停列表刷新，继续显示必要的状态通知。 [Slint ListView](https://docs.slint.dev/latest/docs/slint/reference/std-widgets/views/listview/)

## 性能基线

在同一台 Windows 机器上，以 8000／8001 和现有浏览器控制台为基线，在同一版本、数据量和负载下测量桌面原型。记录前后端各自开销以及整套进程的总开销。先使用可重复的上游夹具测量网关开销，再用实际 UM 请求验证端到端体验。

- **后台与桌面。** 记录冷启动到首次可操作、托盘恢复到窗口可操作的耗时，以及主窗口打开、关闭到托盘后的 CPU 和内存。观察窗口关闭后的刷新活动。
- **网关与控制台。** 记录 8000 的首个流式输出耗时、并发吞吐和 p95 延迟，以及 8001 查询长账本和日志时的延迟、CPU 和内存。比较窗口打开、托盘驻留及桌面应用退出时的请求表现。
- **页面。** 记录首页可操作时间、账本和日志列表的打开与滚动表现。根据结果评估按需加载、列表渲染、轮询频率和动效的成本，再为实际工作负载定量化目标。
- **日志及时性。** 用同一台 Windows 机器和相同事件负载测量日志写入到前台列表可见的延迟。原型阶段的待验证目标为 p95 ≤ 500 毫秒。记录连续写入时的滚动表现、断线补读结果，以及启用日志订阅前后 8000 流式请求延迟的变化。

## 后续跨平台与手机反代

首版将 Windows 专用的托盘、自启、进程管理和浏览器交互留在平台入口。核心网关、请求协议、控制台页面及接口可独立复用。后续根据目标设备的系统生命周期、网络和资源预算评估平台适配。

手机反代作为后续可行性评估。分别考虑手机作为客户端访问本机网关，以及手机承载反代进程。前者复用网关接口并单独确定访问边界。后者先验证目标系统的后台持续运行、网络切换、耗电和认证接管，再决定实现形态。 [控制台访问边界](../../GLOSSARY.md)

## 原型验证

- 首轮 Slint 原型聚焦状态总览和实时日志，在相同数据量和负载下对照现有浏览器控制台记录 Windows 实测结果。
- 在 Windows 登录后启动桌面应用，关闭窗口后用托盘恢复。重复打开入口时复用原窗口。在窗口关闭期间向 8000 发起请求，确认服务可继续使用。
- 验证桌面版能读取 8001 状态并沿用现有管理操作。需要人工接管时打开可见 Edge，同一轮核验通过后同步更新窗口和托盘状态。
- 在桌面 App 保存 UM 账号密码后，重启 App 和 8000。使专用 Edge 在可信的 UMPASS 官方页呈现空表单，确认 8000 补填并提交一次，核验通过后窗口与托盘显示「已登录」。Duo 需要本人确认时，验证 App 显示对应提示并跟踪同一轮结果。
- 验证右侧请求详情关闭后保留列表筛选和滚动位置。验证 Windows 浅色和深色主题、键盘焦点、缩放及睡眠唤醒后的主要操作。按性能基线记录结果。
